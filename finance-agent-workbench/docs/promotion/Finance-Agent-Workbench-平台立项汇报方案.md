# Finance Agent Workbench 智能财务工作台

## 一、项目概述

### 1.1 项目背景

公司财务部门日常面临大量 **Excel 数据核对、分析、报表**工作。以销售回款提成核对为例，每季度需将季度分表与年度汇总逐条比对，核对维度涵盖合同编号、销售人员、客户单位及金额等要素。当前工作流程存在突出痛点：

- **数据分散核对困难**：季度分表与汇总表分属不同文件，字段命名不统一，核对低效易错。
- **人工重复标准不一**：每季度重复相同流程，不同人员标准不一，记录格式不统一。
- **错误回溯困难**：修改后难以追溯原始值/操作人/时间，回滚复杂。
- **分析门槛高**：从数据到归因建议依赖专业建模能力，业务人员无法自助。
- **报告生成耗时**：核对/分析后手工撰写报告，格式内容难一致。

### 1.2 项目目标

构建一个**财务智能工作台平台（Finance Agent Workbench）**，把手工流程改造为 **"文件上传 → 自然语言指令 → 系统自动执行 → 报告输出"** 的标准化、可审计工作流。具体目标：

- 实现 Excel 自动导入、结构化存储与字段识别（含表头智能定位）
- 建立多层匹配逻辑，自动完成核对与**五级差异分级**
- 在**临时库隔离 + 字段级修改日志**机制下执行数据修正，只改勾选单元格
- 按统一模板自动生成**核对报告 / 建模分析报告**（可导出 Word，含图表、三线表排版）
- 将高频流程固化为**集成应用**，业务人员无需建模/脚本知识即可产出专业报告
- 建立完整操作审计日志，实现责任可追溯

### 1.3 业务价值

| 价值维度           | 具体表现                                                           |
| :----------------- | :----------------------------------------------------------------- |
| **效率提升** | 将原需数小时的手工逐条核对/分析压缩至**分钟级**自动完成      |
| **质量保障** | 标准化匹配逻辑 + 五级差异分级，消除人为疏漏，规则一致执行          |
| **风险控制** | 临时库隔离防污染主库、字段级修改日志全链路留痕、写回仅改勾选单元格 |
| **降低门槛** | 业务人员**无需建模/编程知识**，一句话即可产出建模分析与报告  |
| **成本节约** | 减少重复性人力投入；**本地确定性计算**大幅降低 Token 消耗    |
| **可复用性** | 支持多年度、多项目、多应用独立运行，一次部署长期使用               |

### 1.4 定位与适用范围

Finance Agent Workbench 定位为**财务部门内部智能工作台**，核心是**"AI 辅助决策、本地确定计算、全程可审计"**。系统**不替代财务人员的专业判断**，而是将规则明确、重复性高的核对与分析自动化，财务人员仅在关键节点做决策。适用于：

- 销售回款提成的季度核对与年度汇总
- 其他"明细表 vs 汇总表"模式的财务数据核对
- 财务数据建模、趋势分析与报告生成等周期性工作

## 二、平台架构

### 2.1 全局架构

```
┌────────────────────────────────────────────────────────┐
│  ① 交互层：浏览器（工作台总览 / AI 配置 / 项目空间 /     │
│              集成应用一 / 集成应用二）                  │
├────────────────────────────────────────────────────────┤
│  ② AI 模型层：理解意图、引导建模、差异归因、撰写报告     │
│              （仅辅助，不执行确定性计算）               │
├────────────────────────────────────────────────────────┤
│  ③ 应用层：统一引擎承载（项目空间 + 集成应用）           │
│        ---- 隐藏项目组件（每个应用=一个隐藏项目）----    │
├────────────────────────────────────────────────────────┤
│  ④ 工具层：Excel 解析/写回、五级差异分级、32 模型、      │
│              图表生成、run_command/run_python_code       │
├────────────────────────────────────────────────────────┤
│  ⑤ 存储层：SQLite 数据平面（data_* 表）+ 临时库快照      │
│              + 项目数据索引（仅变量索引，不读全量）      │
├────────────────────────────────────────────────────────┤
│  ⑥ 知识/配置层：.github skills（data-reconcile /         │
│                  financial-modeling）+ 报告模板 + 字段映射│
└────────────────────────────────────────────────────────┘
```

| 层          | 核心职责                         | 关键约束                     |
| :---------- | :------------------------------- | :--------------------------- |
| 交互层      | 浏览器界面（总览/配置/两种形态） | 图形化，无需命令行           |
| AI 模型层   | 意图理解、引导、归因、报告       | 仅处理文本，不执行确定性计算 |
| 应用层      | 统一引擎承载两种形态             | 复用主工作台基础设施         |
| 工具层      | 确定性计算（秒级、0 Token）      | 纯算法，不消耗 Token         |
| 存储层      | 数据平面 + 临时库快照 + 变量索引 | 数据按 project_id 隔离       |
| 知识/配置层 | Skill / 模型目录 / 报告模板      | 声明式，可插拔               |

### 2.2 智能体框架

智能体是平台的"大脑"，其**框架设计如下**：

- **三层渐进式加载**：L0（agent.md 常驻）/ L1（SKILL.md 按需）/ L2（资源用时读）——对齐 VS Code Copilot 三层模型，**省算力**
- **本地确定性计算 + AI 辅助**：核对/分级/建模/图表优先调用本地 Python脚本；AI 只做引导/归因/报告
- **工具调用能力**：30 类工具，灵活可扩展
- **沙箱 + 多工作模式**：文件工具限定项目工作目录；`人工审批` / `全自动` 双模式
- **全链路可审计**：字段级修改日志、会话计时、本地操作日志、活动 run 注册表

### 2.4 Skill 体系

Skill 是承载财务方法论的"智能模块"，设计如下：

- **声明式、可插拔**：每次业务方法论浓缩为一个 Skill及其资源文件，**不改核心代码**
- **每个集成应用适配专属 Skill**：应用一装 `data-reconcile skill`（数据核对专用工具）、应用二装 `financial-modeling skill`（财务建模专用工具），**收敛 AI 职责边界**
- **领域知识丰富**：32 财务模型 A-G 分类 + 24 图表模板 L1/L2/L3 档位）

## 三、核心功能一：项目空间（对话工作台）

> 承接**长尾自由任务**。每个项目空间由"对话窗口 + 智能体 + 双 Skill"组成，适合灵活提问、查数、临时分析。

### 3.1 功能组成

| 组成                   | 说明                                                       |
| :--------------------- | :--------------------------------------------------------- |
| **对话窗口**     | 你与 AI 的消息流；空状态有"✨ 尝试这样开始""💡 我能做什么" |
| **智能体**       | 通用智能体，可调用全部 Skill 与工具                        |
| **双 Skill**     | `data-reconcile` / `financial-modeling` 都可触发       |
| **项目目录抽屉** | 管理项目文件（新建/上传/右键），双击预览                   |
| **输入工具行**   | 模型选择器、工作模式（人工审批/全自动）、项目目录、数据库  |

### 3.2 核心能力

- **自然语言驱动**：输入"帮我核对这份 Excel 的金额"，AI 读取、分析、展示结果
- **数据平面内操作**：Excel 导入后物化为 SQLite 表，AI 在库内分析，**不动本地源文件**
- **项目文件管理**：目录树（新建/上传/文件夹），双击 Excel 调本机程序、md/pdf/图预览
- **工作模式**：`人工审批`（写回前确认）/ `全自动`（直接执行）

### 3.3 创新点

- **AI 只输入数据库变量索引**：引导时只传列名索引，**不读全量数据** 省算力、数据不出域
- **沙箱边界**：文件工具限定项目目录，写操作审批 ，**严控 AI 操作边界**

## 四、集成应用

> 把高频流程**固化为向导**。每个应用由**图形步骤向导 、智能体与专属 Skill组成**。

### 4.1 应用一：数据核对与校验

#### 功能

将 data-reconcile 核对方法论固化为 **SPSS 式 6 步向导**：

| 步骤         | 功能                                         |
| :----------- | :------------------------------------------- |
| ① 数据文件  | 选依据表 + 分表，上传/管理项目数据库         |
| ② 匹配键    | 三级匹配键（合同编号→人员→客户，一级必填） |
| ③ 核对变量  | 选核对金额列（带 AI 推荐）                   |
| ④ 容差&策略 | 设容差、匹配不上处理策略、A 类自动写回开关   |
| ⑤ 校验      | 自动核对 → 五级差异分级 + 多轮审计闭环      |
| ⑥ 修改      | 勾选差异 → 确定性写回 → 输出文件           |

#### 创新点

**① 五级差异分级 + 多轮审计闭环**

核对结果自动分为 **OK / A1（漏填缺失）/ A2（小额误差）/ B（待确认）/ C（无法匹配）** 五级，未匹配记录可升级为待审计项，人工决策（补录/忽略/确认对应关系）后进入下一轮核对，直至清零。形成**"机器分级 + 人工审计 + 闭环迭代"**，既高效又保留财务专业判断。

**② 项目数据库内写回**

- 核对/写回在**独立临时库快照**执行，**主库零污染**
- **精确写回**：只改勾选单元格（A1/A2），**未改动区域保持原样**
- **字段级修改日志**（记录改前/后值）+ 文件锁检测（写回前检测文件占用）

### 4.2 应用二：财务建模与分析

#### 功能

将 financial-modeling 方法论固化为 **AI 引导式 4 步向导**：

| 步骤              | 功能                                                |
| :---------------- | :-------------------------------------------------- |
| ① 诉求与数据     | 一句话目标 + 多文件勾选（自动合并建模）             |
| ② 宏观建模与映射 | AI 推荐模型（32 个 A-G 分类）+ 变量自动映射         |
| ③ 图表风格       | 复杂度/偏好类型/配色 + AI 推荐图表清单              |
| ④ AI 撰写报告    | 确定性执行 → AI 报告 → 内嵌预览（编辑/导出 Word） |

#### 创新点

**① 多文件合并引擎**：跨文件按同构/共同键自动合并，统一建模，能够实现多表统一分析

**② 32 个财务模型**：A-G 七大类（报表/预算/成本/绩效/资本/营运/统计），AI 按诉求自动推荐，业务人员无需建模知识

**③ 报告产出**：**核心观点 / 分析基础 / 分析过程 / 结论建议** 结构 + 专业排版（含图表、三线表），支持md文档在线编辑渲染与**导出 （支持Word、pdf、html多种格式）**

**④ 历史记录沉淀**：所有报告留存，可预览、删除

## 六、技术选型依据

财务场景对可解释性、审计追踪、数据安全、操作闭环有高要求，本平台选择 **"Web 智能体工作台 + 本地确定性引擎"** 架构：

### 6.1 可解释性

- **Web 图形界面**：文件读写、脚本执行、核对结果均有明确输出，用户可实时观察
- **本地确定性引擎**：核对/分级/写回由本地 Python 完成，逻辑确定、可复现

### 6.2 审计追踪

平台提供**多链路留痕**（全本地）：

1. **字段级修改日志**（记录改前/后值）
2. **运行记录**（会话计时 + 本地操作日志 + 活动 run 注册表）
3. **临时库快照**（核对/写回在独立临时库，主库零污染）

### 6.3 财务数据敏感性

- **数据全本地**：`data/app.db` + 产物目录全部本机保存，**离线运行不外传**
- **服务绑定 `127.0.0.1`**：外网不可达
- **模型可选内网本地模型或外网资源**：兼容两种，数据不出域

### 6.4 操作闭环

- **六步/四步向导**：单一界面完成"文件→匹配→核对→审计→写回/报告"
- **双工作模式**：人工审批确保写回前征求确认，符合财务习惯

## 八、安全性与合规性

### 8.1 数据隔离

- **项目空间隔离**：每个业务/应用独立隐藏项目（`__app_recon__` / `__app_finmod__`）+ 独立目录，数据按 `project_id` 隔离
- **数据分层**：上传 Excel → 物化为 SQLite 表（分析只读）；修改在独立临时库快照内并留痕，**主库零污染**

### 8.2 访问控制与追溯

- **本地单机**：运行在用户电脑，无多用户权限管理
- **操作追溯**：字段级修改日志 + 运行记录，可回溯执行人/时间/前后值
- **双工作模式**：人工审批确保写回前征求确认

### 8.3 敏感信息与数据安全

- **数据全本地**、服务绑定 `127.0.0.1` 外网不可达
- **AI 只输入数据库变量索引**（读列名/类型，不读全量数据）——即使联网调模型，也不泄露完整敏感数据
- **模型可选内网本地模型**（数据全程不出域）或外网资源（仅传结构化摘要）

### 8.4 操作审计日志

- **字段级修改日志**（列 + 前后值）
- **运行记录**（会话时长 + 本地操作日志 + 活动 run 注册表）
- **报告留痕**（每份报告含来源 run_id，可回溯执行）

## 九、扩展性与维护

### 9.1 新增对账/分析规则

- Skill 声明式：新增业务规则直接加/改 Skill，**不改核心代码**
- 模型库（32 个）、图表库（24 类）通过 `references/` 配置扩展

### 9.2 新增集成应用

基于**隐藏项目组件**，新增一个应用只需加前端页 + 加后端端点 + 建隐藏项目，**完全复用主工作台基础设施**，成本极低。

### 9.3 模型替换或升级

- 支持 DeepSeek / GLM / 千问 / 内网模型多供应商，随时切换/测试

### 9.4 运维监控与异常处理

| 异常场景              | 检测机制                          | 处理措施                                 |
| :-------------------- | :-------------------------------- | :--------------------------------------- |
| Excel 被其他程序打开  | 文件锁检测                        | 提示关闭重试，不强行写入                 |
| 网络中断 / 模型不可用 | 连接检测                          | 核对/建模/图表**确定性降级**仍可用 |
| 数据格式异常          | 表头智能定位                      | 引导用户确认表头/锚点                    |
| 重复执行              | 文件哈希去重 + 幂等               | 复用已有导入                             |
| 系统崩溃              | 临时库快照 + 活动 run 注册表      | `cleanup_stale` 兜底清理               |
| 运行垃圾堆积          | `cleanup_stale`（mtime 超 24h） | 自动清理，活动 run 保护                  |
